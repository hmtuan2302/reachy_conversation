# Barge-in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In `reachy-demo agent`, the user can stop Reachy mid-answer by saying a stop command. Playback ducks to 25% while the user talks, and other speech heard mid-answer is dropped.

**Architecture:** An energy VAD taps the mic stream and drives a gain that `play_and_save` applies to paced playback. `converse` runs each answer (LLM, then speech) as one asyncio task. Turns heard while that task runs go to a DeepSeek intent classifier: a stop cancels the task (killing ffplay), and any follow-up text becomes the next turn. Anything else is dropped.

**Tech Stack:** Python 3.12, asyncio, numpy, httpx (MockTransport in tests), pytest-asyncio (auto mode).

**Spec:** [docs/superpowers/specs/2026-11-16-barge-in-design.md](../specs/2026-11-16-barge-in-design.md)

## Global Constraints
- Done = `uv run ruff format . && uv run ruff check .`, `uv run mypy` (strict), `uv run pytest` all green.
- No new dependencies.
- Duck gain `0.25`. VAD onset `150 ms`, hangover `VAD_HANGOVER_MS` (default `450`). `VAD_RMS` default `500`.
- Playback lead `200 ms`. The saved WAV is always full volume.
- Classify timeout `2 s`. Any classify failure gives `Intent(stop=False, rest="")` and never cancels.
- Output copy is exact: `  (stopped)` and `  (ignored: <text>)`.
- A cancelled answer and the stop turn are not added to agent history.
- Shortcuts with a known limit get `# shortcut: <limit>, <when to upgrade>`.

## Review Focus
- **Stop during the text phase** (LLM still streaming, before speech): the answer is cancelled with the `bot:` line closed by a newline. This is pinned in Task 4, `test_stop_mid_answer_cancels_and_answers_rest`.
- **Several sentences during one answer** ("hmm", then "stop"): the first is ignored and the second stops. Each is classified in order. This is pinned in Task 4, `test_ignored_then_stop`.
- **The input ends while an answer is running** (`--file`): the answer finishes, then the program exits. Nothing hangs. This is pinned in Task 4, `test_input_end_waits_for_running_answer`.
- **Ctrl-C or cancel during paced playback:** the player is killed at once, the WAV of what was received is saved, and `CancelledError` propagates. This is pinned in Task 2, `test_cancel_kills_player_and_saves`.
- **A stop with nothing after it** ("stop"): nothing is answered next, and Reachy just listens. This is pinned in Task 4, `test_stop_alone_answers_nothing`.

- [ ] **Step 2:** `uv run pytest tests/unit/test_agent_cli.py -v`. Expect the new tests to FAIL and the old ones to PASS.
- [ ] **Step 3: Implement `converse`.** Move the body of one answer (print, stream, speak, the error notes) into an inner `async def answer(text)` run as a task. With `classify`, the main loop waits on the answer task or the next queued turn, whichever comes first. A turn heard mid-answer is awaited through `classify`:
  - On stop: cancel the task and `await` it. Awaiting means no chunk of the old answer can run afterwards, so no generation counter is needed; this replaces the spec's counter. If the `bot:` line is still open (text phase), write `\n`. Write `  (stopped)\n`. A non-empty `rest` becomes the next turn.
  - On not-stop: hold `  (ignored: <text>)` and print it after the answer's own lines end. Drop held notes if the answer is cancelled.

  End of input (`None`) still lets the running answer finish.
